- What is on-chain now (two aspects, both devnet + gasless, players hold 0 SOL): (1) DICE - every roll goes through MagicBlock VRF on the ER (human via the player's delegated dice PDA gfgplayerd signed by the session key; computers via the house sponsor key server-side). The roll result plus entropy seed land in the dice PDA and the roll tx signature is the verifiable proof. (2) REWARDS - a 1st-place win that had a valid on-chain roll fires record_points on the player's points PDA (gfgpoints); it stores total_points, award_count, last_points/last_reason/last_match_ref where last_match_ref = first 8 bytes of the winning roll sig, binding the reward to the exact roll. The record_points tx signature is the authoritative receipt. What stays off-chain: board state, token moves, turns, and Supabase profile totals (aggregation/fallback only).
- On-chain points (Scope B, implemented + verified live on devnet): new PlayerPoints ledger account (seed gfgpoints) + initialize_points/delegate_points/record_points instructions on the same delegated gfg-dice program (program id unchanged).
- Relay handleDelegate now creates AND delegates BOTH per-player PDAs (dice gfgplayerd + points gfgpoints) in one idempotent call; fresh onboarding = 4 steps ~0.0086 SOL; per-player spend cap default raised 0.005 -> 0.012 SOL (covers two PDAs with margin).
- Client recordPoints(points, reason, matchRef): pure gasless ER write (session key signs, 0-SOL player) returning the receipt signature; matchRefFromSignature = first 8 bytes of the proof-roll sig as u64; fetchPointsPda reads the player's own ledger; POINT_REASONS.WIN_1ST=1.
- win-detection: after the Supabase +100 1st-place award (proof roll gated), fires recordPoints(100, 1, matchRef) as a soft-fail mirror that never blocks the win UX, and logs the receipt explorer link.
- Admin tracker lists each wallet's dice PDA AND points PDA (live delegation status); dashboard renders both. Profile page adds "Your on-chain points ledger" card (own account only, gasless read).
- Supabase stays aggregation/fallback; the on-chain record is the permanent verifiable layer (re-sync on devnet wipe).
