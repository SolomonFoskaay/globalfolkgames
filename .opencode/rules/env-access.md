# Env Access — HARD RULE (do not read .env silently)

This rule is auto-loaded every session. It is NON-NEGOTIABLE.

- NEVER read `.env`, `.env.*`, `~/.config/solana/id.json`, or any file containing `GFG_Gasless_Sponsor_Keypair`, `GFG_Arc_Gasless_Sponsor_Key`, `GFG_DEVNET_RPC`, `GFG_Arc_RPC`, `GFG_OPERATOR_TOKEN`, `DYNAMIC_API_TOKEN`, or other secrets without the owner's explicit manual approval in that turn.
- If a deploy or relay task needs a secret, ASK FIRST: "I need GFG_DEVNET_RPC (Alchemy) and the sponsor id.json to deploy to devnet via MagicBlock ER — may I read .env/id.json for this deploy?" Wait for a clear "yes".
- When approved, read only the specific value needed, never dump the whole file into logs or commit it. The relay and scripts already load .env via `scripts/load-env.mjs` at runtime — the agent should prefer that path and not copy secrets into code.
- For deploys: use the Alchemy RPC from env (never public `api.devnet.solana.com` for deploys — it times out), and sign with the deployer/sponsor `id.json`. All writes stay gasless via MagicBlock ER (see below). If the owner says no, STOP and explain what cannot be done without it.
- Violating this is a hard stop — do not proceed with the task.

# Gasless ER Rule — HARD RULE (all features via MagicBlock ER)

- Every on-chain feature (dice VRF, record_points, record_global_points, credit_premium_points, activate_subscription, admin_cancel_subscription, spend, AGM post/match/lock/settle, P2C bank, etc.) MUST run on the MagicBlock Ephemeral Rollup (ER), not direct base-layer Solana writes. Base-layer is only for one-time `initialize` + `delegate` (rent + ER session, sponsor pays ~0.0013 SOL), the one-time program (build+deploy of the .so once), and one-time token vault moves (MagicBlock Ephemeral SPL Token deposit/withdraw). After delegation, every write is gasless on the ER (session key or sponsor key signs, tx fee 0, VRF queue `5hBR...` free, normal ER tx = 0 lamports in the current release).
- NEVER ship a feature whose writes go straight to base layer via `sendMagicTx`. This is the ONE bug that made the AGM order book "cost per transaction": the relay posted orders on base instead of delegating the order/settlement/bank PDAs on the ER first. Correct order: `initialize + delegate` each new account type ONCE on first use (relay/sponsor, idempotent), then every write goes through the ER RPC with region-aware targeting (`getDelegationStatus -> fqdn`, `src/gfg-rpc.js`).
- Wallet BALANCES + DEPOSITS + WITHDRAWALS are supported by MagicBlock ER via **Ephemeral SPL Tokens** (program `SPLxh1LVZzEkX99H6rqYizhytLWPZVV296zyYDPagv2`): eATA ledger + per-mint Global Vault. Balance = `getTokenAccountsByOwner`/`getBalance` on ER RPC or hosted `/v1/spl/balance`; deposit = `/v1/spl/deposit` (base vault move, then gasless in-ER transfers); withdraw = `/v1/spl/withdraw`. A wallet with 0 SOL but USDC/USDT is a SUPPORTED player (devnet default USDC mint `4zMMC9srt5Ri5X14GAgXhaHii3GnPAEERYPJgZJDncDU`).
- Dice MUST use MagicBlock **ER VRF** (free queue `5hBR571...` on ER), never the paid base-layer VRF queue (`Cuj97...`). `src/magicblock-er-vrf.js` is the only VRF path on ludo-lab.
- Deployer/sponsor is `~/.config/solana/id.json` (devnet) / `GFG_Gasless_Sponsor_Keypair` env — it signs all sponsored onboarding and admin writes. Players hold 0 SOL by design.
- **Arc rail (arcv2m16):** the EVM sponsor/relayer is `GFG_Arc_Gasless_Sponsor_Key` (a 32-byte hex key) with public `GFG_Arc_Gasless_Sponsor_Address`, plus `GFG_Arc_RPC`. Treat these exactly like mainnet secrets: never commit, never log, never put them in `public/` or any client payload. On Arc the gas token is USDC, so the sponsor only needs test/mainnet USDC. Arc Testnet is reached at `https://rpc.testnet.arc.io` (chain id 5042002); the EVM game code lives in `evm/`.
- When manually upgrading (activate) or admin cancelling, the write is still on the ER (gasless to the user, sponsor is payer). Do NOT force a base-layer undelegate -> base write -> re-delegate dance for every admin write unless the PDA is not yet delegated. Prefer ER RPC (`src/gfg-rpc.js` 3-region registry + region-aware `getDelegationStatus -> fqdn` targeting) for all post-delegation writes.
- Program DEPLOY: the one-time `.so` build+upgrade goes to the MagicBlock region/router RPC when MagicBlock supports it; devnet-so-far it is a base-layer `solana program deploy` (one-time, unavoidable, once). Alchemy (`GFG_DEVNET_RPC`) is ONLY the fast/public-devnet RPC for embedded-wallet SPL BALANCE reads and flaky-public-RPC fallback — never a feature-write path, never per-game-transaction.
- Runtime alert: Solana/ER SVM caps a function's stack frame near 4 KB. A struct with a big array (e.g. `[u64; 512]`) overflows the frame and the program fails at runtime even though it compiles. Keep account structs small, or use `Box`/fixed smaller arrays when the compile may warn "Stack offset ... exceeded max offset".
- Scope is `/ludo-lab` (full on-chain game) only. Never touch `/ludo` (legacy). Surgical edits only — verify `ludo-lab` wiring stays green (`npm run build`, harness) before commit/push.
