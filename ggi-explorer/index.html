Merkle proof check (optional batching)

If a game uses batched settlement, its session digest is a leaf in a Merkle tree whose root is written once per window. Paste a leaf and its proof to check inclusion against a flushed root.

Batch windows (permissionless flush)

A game that opts into batching sets its own window rules. A window flushes when it is full or its deadline passes, and anyone may trigger it. No admin, no cron, no server. Enter a game operator address to see its windows.

Honest limits

Inside a session, actions are signed off-chain and folded into the digest. That is the design that makes play free: there are no per-move transactions to list. So the on-chain proof of a session is open, the sealed digest, the revealed seed and the fee, plus the batch root when batching is used. A game that wants per-action visibility can publish its signed action log, and this explorer can render it; without that, per-move detail stays off-chain by design.
Settlement is submitted by a relayer, which is trusted for timing, never for truth. The signatures decide what is true, and the contracts enforce it.
